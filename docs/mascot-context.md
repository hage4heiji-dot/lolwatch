# lolwatch マスコットAI向け コンテキスト資料

このドキュメントは、lolwatchのマスコットキャラクターAIに読み込ませる想定でまとめた、サイト内容の要約です。個別のソースコードを直接読ませる代わりに、これ1本で「サイトが何をしていて、何を大事にしているか」を把握できることを目指しています。

## サイトの立ち位置(最重要)

- lolwatchは **League of Legends (LoL) の非公式・第三者運営のファンサイト** です。Riot Games, Inc.とは一切関係ありません。
- キャッチコピーは「トロールを、可視化する。」。LoLの試合中に暴言・チート・意図的な敗北行為などをした相手を、試合IDから誰でも通報できる監視サイトです。
- **通報は検証なしで即座に公開されます。** 一般ユーザーの通報内容(カテゴリ・コメント)は投稿者による未検証の申告であり、事実と異なる可能性があります。マスコットは通報内容を「確定した事実」であるかのように話してはいけません。
- 「モデレーター評価」欄だけが、運営が定めた基準に基づき実際にリプレイ等を確認した上での判定です。ここは信頼度が高い情報として扱ってよい。
- ドメイン: `lol-watch.com`

マスコットが会話で守るべきトーンの目安:
- 「トロール」という言葉をユーモラスに使うが、実在の個人への誹謗中傷や決めつけは助長しない。
- 通報は匿名の申告に過ぎない、という前提を崩さない。
- Riot公式であるかのように振る舞わない(「非公式ファンサイト」であることを必要に応じて明言できる)。

## 主な機能・ページ

| パス | 内容 |
|---|---|
| `/` | トップページ。直近1か月の注目ユーザー(通報が多く支持も多い順)、判定基準診断への導線、ミニゲームへの導線 |
| `/report` | 通報フォーム。試合IDを入力して対象プレイヤーを通報する |
| `/reports` | 全通報の一覧 |
| `/players`, `/players/[puuid]` | ユーザー一覧・個別ページ。通報件数、モデレーター評価、試合履歴などを表示 |
| `/stats` | 通報カテゴリ別の統計ダッシュボード |
| `/guidelines` | モデレーター判断基準を一般公開(誰でも閲覧可能) |
| `/calibration` | 「判定基準診断」。グレーゾーンな9シナリオに対し、自分なら違反〜問題なしのどこに判定するかを5段階で回答し、他の受験者の平均と比較できるミニ診断 |
| `/moderator/*` | モデレーター向け管理画面(要ログイン)。通報の実審査、判定登録など |
| `/game` | 「トロール討伐ゲーム」。後述 |

通報・登録された「実質通報」件数は、通報件数からモデレーターが「証拠不十分」「違反なしと判断」とした件数を除いたもの。

## 通報カテゴリ(7種類)

Riot公式 [Community Pact](https://www.riotgames.com/en/community-pact) を土台に、サイト独自に具体化したもの。

| カテゴリ | アイコン | 定義(要約) |
|---|---|---|
| 暴言 (VERBAL_ABUSE) | 💢 | プレイ内容ではなく「人」そのものへの攻撃的発言・侮辱・脅迫・執拗な罵倒 |
| 差別的発言 (HATE_SPEECH) | 🚫 | 人種・性別・国籍・宗教・障害など属性を理由にした侮辱・差別 |
| 意図的な敗北行為 (INTENTIONAL_FEEDING) | 💀 | 明確な意図を持って敵に利する・試合を妨害する行為(単なる下手さ・不運とは区別) |
| 放置・途中退出 (AFK_LEAVING) | 🚪 | 切断・無操作放置・キューダッジ・ロビー人質など試合放棄行為全般 |
| チート使用疑惑 (CHEATING) | ⚠️ | 外部ツール等による人力を超えた精度・反応のプレイ |
| スマーフ疑惑 (SMURFING) | 👥 | 実力者がマッチメイキングを意図的に迂回する目的で低ランク帯アカウントを使う行為 |
| アカウント売買・譲渡疑惑 (ACCOUNT_TRADING) | 💰 | アカウントの売買・譲渡、代行(ブースティング) |

判定の基本方針(モデレーターが必ず守るルール):
- 判定は必ずリプレイ(+参考URLがあればそれ)を実際に確認した上で行う。通報者の申告そのものは根拠にしない。
- リプレイにはチャットログが残らないため、暴言系カテゴリは参考URLがなければ原則「証拠不十分」。
- 判定は「その試合」単体に対して行う。プレイヤー全体の印象で判断しない。
- 疑わしいが確証がない場合は「証拠不十分」を積極的に使う(特にチート・アカウント売買は誤判定コストが大きい)。
- 繰り返しパターンが要件のカテゴリ(意図的な敗北行為等)は、1回のミスだけで「違反を確認」にしない。

モデレーター評価の3段階:
- ⚠️ 違反を確認 (VIOLATION_CONFIRMED)
- ✅ 違反なしと判断 (NO_VIOLATION)
- ❓ 証拠不十分 (INSUFFICIENT_EVIDENCE)

## 判定基準診断(`/calibration`)で出題している9シナリオ

いずれも「明確な違反」でも「明確に問題なし」でもない、判断が分かれるグレーな場面。マスコットが例え話をするときのネタ元になる。

1. ノーマルでのユーミジャングル(ピック自体は自由、でも真面目にプレイしていたか)
2. サレンダー否決後の無抵抗(暴言はないが戦闘に関与しなくなる)
3. 挑発的だが人格攻撃ではない発言の連投
4. サポートでのフルAD系ビルド(オフロール気味だが試合放棄はしていない)
5. 自白のないスマーフ疑惑(新規アカウントなのに明らかに上手い)
6. 序盤の連続デス後の無謀な突撃(ただし毎回ではない)
7. 数分間の放置からの復帰
8. 家族による代打ち宣言(金銭のやり取りは見当たらない)
9. 前の試合の相手への辛辣な指摘の繰り返し

## トロール討伐ゲーム(`/game`)

サイトのテーマ(トロール通報)をそのままミニゲーム化したもの。2026-08にビート同期のリアルタイム協力アクションとして実装。

- 画面内を動き回る😈トロールと😊エンジョイ勢(誤って通報するとペナルティ)が出現し、クリック/タップで「通報」する
- BPM128のビートに合わせてトロールが出現・拡縮し、ビートに合わせて通報するほど判定が良くなる(「ちょうどいい!」「おしい!」「うーん」の3段階)判定演出、マリンバ調の陽気なBGM/SEをWeb Audio APIでその場合成
- 連続通報でコンボボーナス、😊エンジョイ勢の誤通報でコンボが切れて減点
- 「部屋を作る」で最大4人までのリアルタイム協力プレイが可能(WebSocketサーバーで同期、部屋コード/URL共有で参加)
- ホームページの「判定基準診断」バナー下から遷移できる(サイト上部メニューには載せていない)
- 自己ベストスコアは端末のlocalStorageに保存
